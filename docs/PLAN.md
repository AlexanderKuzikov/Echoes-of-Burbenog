## Что это

3D tower defense в браузере. Референс принципов, не клон: Warcraft III / Burbenog TD. Оригинальный
visual identity, собственные модели и палитра. Solo — единственный режим в фокусе, слой сессий
заморожен и работает.

## Где мы на самом деле

Игрок получает карту 40×40 с одним замкнутым кольцом и четырьмя подводами из углов, двенадцать ниш
по три в квартале, три башни, семь видов врагов и десять волн, которые идут 10–15 минут в зависимости
от того, что построено. Камеру можно вращать, зумить и сбрасывать, клик по нише не проходит сквозь
камень. Убийство платит золотом, утечка отнимает целостность ядра, победа — на десятой волне.

**Главное правило фазы: работаем только над тем, что видно и в что играют. Инфраструктура не
расширяется.** `test:core` больше не контракт, а требование красного прогона к слою контента не
применяется: там критерий — что в это интересно играть, и он проверяется глазами, кадром и игрой.

Почему так вышло: единицей работы была «задача с проверяемым критерием», и всё, что нельзя было
доказать, откладывалось. А игра — как раз то, что не доказывается. `EOB-003` («выбрать приоритетный
subset механик из research brief») висит открытым с первого дня: сначала был выбран транспорт, а не
игра.

## Карта и волны: что заморожено

Имена, по которым сессии не должны разойтись. Волна, ссылающаяся на вид, который никто не рисует, —
это волна, которую клиент не покажет.

| Что | Имена |
|-|-|
| Маршруты | `burrow-north`, `burrow-east`, `burrow-south`, `burrow-west` |
| Враги | `husk`, `runner`, `wisp`, `swarmling`, `carapace`, `mote`, `maw` |
| Башни | `pulse-spire`, `grove-lens`, `frost-relay` — без новых типов |

Геометрия, измеренная по коду, а не заявленная: карта 40×40, кольцо полуразмером 9.4, круг **104.0**
(подвод проходится в обе стороны), дорог 132.8, ядро в центре вне дороги, двенадцать ниш по 2.0×2.0 =
5×5 клеток, дорога и камень вырезаны одним растром 0.4. Валюта проектирования — длина **отдельной**
дороги, видимой из места: общий контур принадлежит всем четырём подводам, и в сумме он попадает четыре
раза. Гейт видит 5.28 единицы на дальности Grove Lens против 2.64 у фланка, то есть вдвое, и это
лучшее место на карте.

Решения по волнам, принятые владельцем: **10 волн, матч 10–15 минут в зависимости от сборки** (две
минуты сняты как недостижимые, потолок камеры упирается в канву 3:1 при карте 2:1), **золото около
1000 за матч** при доске 600–840, так что доска закрывается на девятой волне, **подготовка 100–150
тиков**. `mote` — единственный настоящий воздух: у `wisp` в тегах и `ground`, и `air`, поэтому
наземные башни его бьют. Волна кончается только при нуле живых, поэтому каждый враг должен быть
убиваем, а пропуск — это долг, растущий каждый круг.

**Разрез балансировки, который нельзя размывать:** `reward` и `prepTicks` живут в `contact.ts`,
`startingGold`, `waveBounty`, `repairAmount`, стоимости башен и `coreHealth` — в `scenario.ts`. Один
факт в двух файлах, как `EOB-033`, поэтому число называется явно в обоих отчётах.

## Экономика с зубами и прогрессия башни — очередь без номера

Подробно это пункт 5 и 6 плана выше. Здесь только рамка, чтобы выдача не начиналась с нуля: что нужно
по продукту — золото за убийство, золото на старте примерно на одну башню, апгрейд за золото, уровни
1→3 и одна развилка на третьем уровне, шесть веток на три башни. Без развилки апгрейд деградирует в
«вложиться в одну башню», поэтому порядок: сначала экономика с зубами, потом уровни.

Два замера, к разговору о выдаче. Первый, на прежней одноволновой карте: одна волна выигрывается
**одной** башней в 9 случаях из 15 (ниша × башня), лучшая одиночная — `grove-lens` в угловой нише;
`frost-relay` в одиночку не выигрывает нигде; три, четыре и пять башен дают одинаковый тик, то есть
решение принимается один раз. Второй, на кольцевой карте с десятью волнами: доход 1075 (540 наград
за убийства, 315 за волны, 220 на старте) против доски в 600–840, доска закрывается на девятой волне,
и при срезанном доходе матч растягивается с 10.5 до 12 минут, потому что тонкая защита отбивает волны
дольше.

## Как запустить и поиграть

```bash
npm install
npm run dev          # http://localhost:5173 — solo, это режим по умолчанию
npm run server       # только для комнаты, второй терминал; порт 5180
```

Управление в сцене: драг мышью вращает карту, колесо зумит, `R` возвращает исходный вид. **Правый драг
не работает** — он заявлен в подсказке, но картинку не двигает (`EOB-041`). В комнату — два окна на
`http://127.0.0.1:5173/?room=<имя>`. Место хранится в `localStorage`, поэтому оба окна открыть **до**
входа в комнату, иначе вторая вкладка заберёт место у первой.

Проверка: `npm run typecheck`, `npm run build`, `npm run test:assets` (те же 11 красных проверок),
`npm test` (сейчас красный на 39 из 48 сценариев, см. `EOB-038`).

## Правила

1. Берётся первая работа из раздела «Что планируется дальше», которая выдана владельцем. Пока не
   сказано «выдавай», номера не расходуются.
2. **Штаб** — основная сессия: обсуждает, решает, выдаёт, принимает и ведёт документацию. **Кодовая
   сессия** — одна на задание: получает задание файлом, пишет код, проверяет, сдаёт. Механика выдачи и
   форма отчёта — `D:\GitHub\knowledge\session-tasks.md`.
3. **Команда запуска кодовой сессии — одна строка:** `<папка репозитория>. Читай docs\tasks\файл-задания.md`.
   Всё остальное живёт в файле задачи, поэтому задание обязано быть самодостаточным: правила, карта
   файлов, команды, что не трогать, куда писать отчёт, порт.
4. **Кодовая сессия не трогает проектную документацию.** Запрещены `docs/PLAN.md`, `docs/CONTEXT.md`,
   `docs/DECISIONS.md`, `docs/ARCHITECTURE.md`, `AGENTS.md` и чужие файлы в `docs/tasks/`. Отчёт
   пишется целиком в свой файл задачи, штаб читает его, проверяет и сам обновляет документацию.
   Причина: сессии работают параллельно, и общий файл документации становится местом конфликта.
5. Не делать «заодно»: не расширять scope, не добавлять зависимости, не рефакторить соседний код.
6. Не перезаписывать чужую незакоммиченную работу. Перед коммитом — `git status` и `git diff`.
7. **Общий рабочий каталог.** Параллельные сессии делят один каталог и один `.git`, а `rebase.autoStash`
   в проекте не задан. Поэтому: чужую незакоммиченную работу не откатывать, **ничего не stash'ить**,
   ошибку сборки в чужом файле не чинить, а сообщать о ней в отчёт.
8. Коммитить только свои файлы, поимённо. `git add -A` запрещён. Ветка `main`. Коммит и push делаются
   без отдельного разрешения — владелец дал его на постоянной основе 2026-09-28. Пока идёт заход с
   несколькими сессиями, push делает штаб после сдачи всех: rebase в общем дереве грозит блокировкой
   индекса, и сессия в нём участвовать не должна.
9. Строгий UTF-8 во всех изменённых текстовых файлах: повреждение кодировки невидимо для `git status`.
10. Сдача — как «на проверке», с числами и кадрами. Отчёт без чисел не принимается.
11. Задача, меняющая картинку, обновляет `docs/screenshots/`; старые кадры удаляются, а не копятся.
    Кадры для публичного набора снимаются с production-сборки, а не копируются из `test-results/`.
12. Нумерация неукоснительна: следующий номер — последний принятый плюс один, отложенные работы
    номеров не занимают, замороженный блок номеров не держит.
13. **Приёмка ведётся штабом, а критерий ставит владелец.** Штаб проверяет замером и игрой, а не
    пересказом отчёта, и говорит, где отчёт неверен. Свои измерения живут в `CONTEXT.md`, отчёт
    сессии — в её файле задачи, и в `PLAN` отчётов нет.
