# 0016 — Экран входа и полный E2E от меню до терминала

> Статус: выдана кодовой сессии
> Приоритет: P0
> Фаза: 5 — Offline singleplayer
> Следующая приёмка: `0017`; фаза 5 на этом закрывается

## Контекст

`0015` принят: матч сохраняется по command log, Load — это пересимуляция до тика тем же путём, что Restart, и восстановленный матч совпадает с сохранённым буквально. Слот есть, но добраться до него можно только кнопкой в доке, а начать игру — только тем, что страница уже загрузилась в preparation.

Два хвоста висят на этот момент. Первый практический: `EOB-021` — сценарий Load читает фазу из живого DOM, а матч после Load снова живой, и под нагрузкой проверка успевает увидеть `victory` вместо `wave`. Это тот же класс, что `EOB-017` и `EOB-019`, и лечится единственным уже проверенным способом: чтение переносится внутрь страницы. Второй продуктовый: у игры нет входа. Слот, который нельзя увидеть при запуске, и кнопка, которая появляется ниоткуда, — это не то, что мы писали в README про `npm run dev`.

## Цель

Игра начинается с экрана входа, из которого можно начать новый матч или продолжить сохранённый, и полный путь от этого экрана до victory проходит в E2E без ручных шагов и без прямых вызовов внутренних функций.

## Обязательные условия

1. **`EOB-021` закрывается до начала работы.** Сценарий Load читает состояние из page-side отметки прибытия, а не из живого DOM. Основание для длинного сценария должно быть устойчивым, иначе каждый его шаг будет флаковать по той же причине.
2. **Правило «это измерение, а не продукт» действует и здесь.** Любая проверка фазы, тика, золота или позы после Load, Restart или входа читается из отметки, снятой в момент, когда состояние было терминальным или остановленным. Живой матч — только для поведения, которое специально проверяется как «идёт».

## Решения штаба (приняты, не переигрывать)

1. **Вход — оверлей в той же странице, без роутинга и без второго HTML.** Один документ, один клиент, один `Simulation`. Отдельная страница входа означала бы второй bootstrap и второй набор состояний ради одного выбора.
2. **Автозагрузки нет.** При наличии слота оверлей показывает его тик и число команд и предлагает Continue или New match. Решение игрока остаётся за игроком — это то же правило, что в `0015`, и оно не пересматривается.
3. **Continue и New match — единственные действия входа.** Никаких «начать заново с другой сложностью», настроек, профилей и списка слотов: их не существует, и придумывать их здесь не место.
4. **New match на экране входа требует подтверждения вторым нажатием.** Оно уничтожает слот, а уничтожение слота — единственное необратимое действие в игре, поэтому оно подтверждается явно. Никаких `window.confirm`: диалог браузера не тестируется и выглядит чужеродно.
5. **Один новый контрол — `MENU`.** Он возвращает к оверлею и ничего не стирает: слот и текущий матч остаются как есть, игрок решает дальше. Никаких других новых контролов.
6. **Терминальный экран не трогаем.** После victory или defeat остаётся текущий result banner плюс уже существующие Restart и New match; набор «Retry / Next / Menu» не вводится.
7. **Никакой art direction.** Оверлей собирается из существующего языка: те же цвета, те же радиусы, тот же шрифт, те же data-testid и aria. Это про вход, а не про внешний вид.

## Входит в задачу

- `index.html` — оверлей входа, кнопки Continue / New match / подтверждение, контрол `MENU`, hook'и и `data-testid`.
- `src/styles.css` — оверлей в существующем языке, адаптив, никакой обрезки подписей по правилам `0015`.
- `src/main.ts` — состояние входа, чтение слота для показа, Continue, New match с подтверждением, `MENU`, отсутствие автозагрузки, восстановление инфраструктуры replay при входе.
- `tests/smoke.spec.ts` — закрытие `EOB-021` и полный путь: вход, новый матч, победа реальными кликами; вход с сохранённым слотом, Continue, совпадение состояния; вход, New match с подтверждением, пустой слот; победа и поражение через вход.
- `docs/ARCHITECTURE.md`, `docs/DECISIONS.md`, `docs/PLAN.md`, `docs/CONTEXT.md`, этот файл, `docs/screenshots/` — контракт и evidence.
- `src/game-core/*`, content, `scripts/*`, `src/asset-budgets.ts`, `src/asset-registry.ts`, `package.json` — не меняются.

## Порядок работы

1. Закрыть `EOB-021`: перенести чтение фазы в сценарии Load на page-side отметку прибытия и убедиться, что сценарий зелёный на нагрузке.
2. Собрать оверлей входа в существующем языке: заголовок, состояние слота (пусто или тик с числом команд), Continue, New match.
3. Состояние входа: пустой слот → только New match; слот есть → Continue и New match; `MENU` возвращает сюда, ничего не стирая; New match на оверлее переходит в подтверждение и только вторым нажатием чистит слот и начинает матч.
4. Continue вызывает тот же путь восстановления, что Load в `0015`, без второй реализации.
5. Не трогать терминальный экран: result banner, Restart и New match остаются как есть.
6. Написать полный E2E: вход → новый матч → реальные клики по pads и Start Wave → victory; и вход с сохранённым слотом → Continue → совпадение состояния. Второй сценарий на поражение.
7. Обновить документацию и `docs/screenshots/`: вход — новая поверхность, она попадает в кадр.

## Acceptance

- `npm run typecheck`, `npm run build` проходят.
- `npm run test:core` — те же `status victory, tick 323, gold 229`.
- `npm run test:assets` — те же 11 красных проверок, артефакт не меняется.
- `npm test` проходит: не меньше 29 сценариев, минимум три полных прогона подряд и нагрузочный `--repeat-each=2` без падений.
- `EOB-021` закрыт: сценарий Load зелёный на десяти прогонах под нагрузкой, а его чтение идёт из отметки прибытия, и это видно в коде теста.
- При запуске страницы с пустым слотом открывается вход, а не preparation; при наличии слота вход показывает его тик и число команд.
- Continue восстанавливает матч, совпадающий с сохранённым: тот же тик, золото, snapshot, `commandCount` и поза, проверка сравнением.
- New match на входе без подтверждения не стирает слот; второе нажатие чистит слот и даёт preparation тика 0.
- `MENU` возвращает к входу, не стирая слот и не меняя состояние матча; из входа можно продолжить.
- Полный путь входа до victory проходит реальными кликами по canvas и по кнопке Start Wave; в сценарии нет прямых вызовов `dispatch` для игрового ввода, а `page.evaluate` используется только для чтения и координат.
- Победа и поражение достигаются через вход, а terminal state и `matchReports` корректны в обоих случаях.
- Подписи входа читаются полностью: та же проверка глифов, что после fix'а `0015`, включая 560 px.
- `?dev` продолжает работать: диагностика появляется только с флагом и оверлей её не ломает.
- Core, content, `scripts/*`, общий модуль бюджетов, реестр моделей и `package.json` в diff не входят; новых зависимостей нет.
- `git status` после `npm test` чистый; `docs/screenshots/` обновлены по правилу штаба.
- Красный прогон обязателен: вернуть автозагрузку слота или убрать подтверждение у New match — соответствующий тест обязан стать красным.

## Не входит

- Settings, сложность, профили, несколько слотов, статистика, достижения, локализация.
- Экран победы с «Next» или «Retry» — терминальный экран не трогаем.
- Menu для multiplayer, лобби, приглашения.
- Save/restore в формате snapshot — `EOB-010`; вход работает поверх command log.
- Изменения баланса, волн, башен, экономики.
- Art direction и новые визуальные элементы.
