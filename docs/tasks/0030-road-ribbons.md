## Почему так вышло — и это моя ошибка, не твоя

`0029` замкнула кольцо, и подвод стал проходиться **дважды в одном маршруте**: враг входит по подводу,
обходит кольцо и выходит по тому же подводу обратно. А код в `map.ts` относит сегмент к контуру, если
сегмент **пройден больше одного раза** — то есть тестирует «сколько раз прошли», а не «сколько
маршрутов его содержат». До замыкания это совпадало: кольцо шли все четыре, подвод ровно один. После —
совпало всё, и подвод стал «контуром».

Правильный тест тот, который уже написан в комментарии над кодом: **контур содержится в более чем
одном маршруте, подвод принадлежит ровно одному.** Проходы внутри одного маршрута не считаются ни
чем.

## Что именно сделать

- **Разделять сегмент по числу содержащих его маршрутов, а не по числу проходов.** В коде это
  `walkCount`, который сейчас копит по всем маршрутам подряд; считать надо по маршрутам: у каждого
  маршрута свой набор ключей сегментов, и «сколько маршрутов содержат этот сегмент» — это то, что
  нужно проверить на единицу больше.
- **Ничего больше не трогать.** Собирание контура обратно в петлю уже правильное — оно идёт по
  концам отрезков, и когда подводы вернутся в свой набор, оно снова даст замкнутое кольцо.
- **Комментарий над кодом привести в соответствие с тем, что он теперь говорит.** Он обещает «кольцо
  обходят все четыре, подвод ровно один» — после твоей правки это снова правда, но формулировка про
  счёт должна совпадать с кодом, иначе следующий человек сломает это снова.

## Что было различение и что стало

**Было — проходы.** `walkCount` копил по всем маршрутам подряд, и сегмент признавался контуром, если
он **пройден больше одного раза**:

```ts
const walkCount = new Map<string, number>();
for (const route of config.map.routes) {
  for (let index = 1; index < route.points.length; index += 1) {
    const key = segmentKey(route.points[index - 1], route.points[index]);
    walkCount.set(key, (walkCount.get(key) ?? 0) + 1);   // +1 за каждый проход, в любом маршруте
  }
}
// и в двух местах проверка на единицу больше:
if ((walkCount.get(key) ?? 0) > 1) { contourSegments.push(segment); }      // контур
if ((walkCount.get(…) ?? 0) !== 1) { break; }                             // конец подвода
```

**Стало — маршруты.** Каждый маршрут кладёт в общий счёт своё **множество** сегментов, а не прибавку
за проход, и всё остальное не тронуто (`routeCount` вместо `walkCount` в тех же двух проверках):

```ts
const routeCount = new Map<string, number>();
for (const route of config.map.routes) {
  const ownSegments = new Set<string>();
  for (let index = 1; index < route.points.length; index += 1) {
    ownSegments.add(segmentKey(route.points[index - 1], route.points[index]));
  }
  for (const own of ownSegments) {
    routeCount.set(own, (routeCount.get(own) ?? 0) + 1);   // +1 за маршрут, а не за проход
  }
}
```

Множество здесь и есть вся разница: маршрут-`circuit` проходит **свой собственный** подвод туда и
обратно, то есть два раза внутри одного маршрута, и счётчик проходов записывал это как «общий». Один
владелец сегмента — сколько бы раз он его ни проходил.

Комментарий над кодом приведён в соответствие: было «counted across the walks», стало «told apart by
how many routes contain it», и рядом добавлено, почему счёт проходов здесь лжёт (иначе следующий
человек напишет обратно то же самое).

## Что не изменилось и почему это важно

Дорога как множество не изменилась ни на единицу, и это не совпадение, а суть правки: менялась не
дорога, а то, **в какую ленту какой сегмент попадает**.

- длина дороги 132.8 и 12 сегментов — как было;
- растр 1408 открытых клеток, 218 блоков камня, 12 ниш — как было;
- расстояние до дороги и **покрытие каждой ниши на трёх дальностях** — совпали до сотой на всех

То есть растр, picking, покрытие и камера были правы не случайно: они берут сегменты из
`roadSegments`, где дедупликация по двум концам уже была правильной. Правилась только вторая
потребительская группировка — та, что строит ленты. Это тот же класс, что `EOB-033`: один факт
(`roadSegments`) читают двое, и ошибка была у того, кто читает его иначе.
